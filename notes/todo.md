## Current Status

- spec.md: frontend core game engine, math/operators (basic, powers/roots, real factorial/gamma via Lanczos plus principal-branch inverse gamma, trig in degrees, inverse, bit-shifting, and digit concatenation (`||`, its own lobby toggle); the 200-point nesting penalty applies to factorial + inverse gamma, not factorial + gamma), scoring system, deck pools (1/2/3/unlimited decks), 5 auto-saved workspaces per round with fixed-size pannable canvas (dealt cards wrap at six per row) + freely draggable card groups, ungroup action (`U` / button), `Z`/`Y` undo & redo, operator hotkeys (`1`–`0` binary, `Shift`+`1`–`0` unary, labelled on the buttons), and full Balatro-inspired pixel-art playable loop (Title, Lobby & Settings, Live Gameplay, Round End, and Match End) are implemented and tested. Balatro-style UI pass is in: left blind/score HUD with tweened value × accuracy chips, floating op cues, Web-Animations pop/shake feedback, target-hit stamp + particles, auto-glide of tall merged stacks, synthesized WebAudio SFX with persisted mute toggle, retro arcade title/lobby/results screens, and a header-less layout whose SFX + navigation live in an Esc menu overlay. Real-time multiplayer now runs against the local table server (`server/`, `npm run dev:server`): authoritative rooms, shared hand/target, server-owned round timer, host-only rules and round control, ready-up lobby, live standings, and a swappable transport seam (`src/multiplayer/`; see notes/multiplayer.md). Audit pass done: `submit` is validated against the round's acceptance band with the error percent recomputed server-side, unknown message types are rejected, socket frames are capped at 32 KiB, the loopback transport hands out snapshots as copies like the socket does, the board is keyboard-playable (tab to a piece, Enter/Space to select), duplicate multiplayer submissions are suppressed, the operator cue shows the real score cost with a per-source cost breakdown in the HUD, tied best boards share the round point (and players who reach first-to-X together draw the series), and dead code (`engine/solver.ts`, unused helpers) is gone. Multiplayer now opens on a lobby selector instead of a room-code box: players set their name, open a public or private lobby (each with a short server-assigned readable code), join by code, or pick a public table from a live list; the table screen shows the code and visibility, the host badge passes to the oldest remaining player when a host leaves, and anyone joining mid-round waits on the bench until the next deal. The frontend is split for readability. `src/App.vue` is a thin shell that owns only the screen switch, the pause menu and the tutorial overlay; every phase is its own component under `src/components/screens/` (title, lobby browser, lobby setup, playing, round end, game over, pause) and the two lobby screens share `src/components/LobbyFrame.vue`. Game state and actions live in `src/app/` composables — `useGame` wires `useMatch` (round, workspaces, room mirror), `useStandings` (seats and winners), `useRoom` (lobby browsing and server sync), `useJuice` (sound, shake, cues, camera glide), `useBoardGestures` (drag, pan, tidy) and `useHotkeys`, with `defaults.ts`, `labels.ts` and `context.ts` for the shared pieces. CSS rules used by more than one screen sit in the shared chrome block at the bottom of `src/style.css`. The same map is written down as READMEs: one for the project, one for `src/`, and a brief one in each folder. The title screen now carries a TUTORIAL button that opens a scrollable player's guide (`src/components/TutorialOverlay.vue`): eight short sections covering target, expression building, board controls, workspaces, scoring, table rules, the operator reference and keys, three screenshots annotated with numbered callouts (`src/components/TutorialShot.vue`), regenerated with `npm run tutorial:shots` (`scripts/capture-tutorial.mjs`, needs `npm run dev` running).
