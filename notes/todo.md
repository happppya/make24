Real-time multiplayer now runs against the local table server (`server/`, `npm run dev:server`): authoritative rooms, shared hand/target, server-owned round timer, host-only rules and round control, ready-up lobby, live standings, and a swappable transport seam (`src/multiplayer/`; see notes/multiplayer.md). Multiplayer now opens on a lobby selector instead of a room-code box: players set their name, open a public or private lobby (each with a short server-assigned readable code), join by code, or pick a public table from a live list; the table screen shows the code and visibility, the host badge passes to the oldest remaining player when a host leaves, and anyone joining mid-round waits on the bench until the next deal. The frontend is split for readability. `src/App.vue` is a thin shell that owns only the screen switch, the pause menu and the tutorial overlay; every phase is its own component under `src/components/screens/` (title, lobby browser, lobby setup, playing, round end, game over, pause) and the two lobby screens share `src/components/LobbyFrame.vue`. Game state and actions live in `src/app/` composables — `useGame` wires `useMatch` (round, workspaces, room mirror), `useStandings` (seats and winners), `useRoom` (lobby browsing and server sync), `useJuice` (sound, shake, cues, camera glide), `useBoardGestures` (drag, pan, tidy) and `useHotkeys`, with `defaults.ts`, `labels.ts` and `context.ts` for the shared pieces. CSS rules used by more than one screen sit in the shared chrome block at the bottom of `src/style.css`. The same map is written down as READMEs: one for the project, one for `src/`, and a brief one in each folder. The title screen now carries a TUTORIAL button that opens a scrollable player's guide (`src/components/TutorialOverlay.vue`): eight short sections covering target, expression building, board controls, workspaces, scoring, table rules, the operator reference and keys, three screenshots annotated with numbered callouts (`src/components/TutorialShot.vue`), regenerated with `npm run tutorial:shots` (`scripts/capture-tutorial.mjs`, needs `npm run dev` running). The playing screen is viewport-locked so the felt and HUD never push the page into a scroll: the board takes the remaining height, the sidebar compacts on short screens (and turns into a top strip below 560px), workspace tabs sit in one row, and the dealt cards are reframed whenever the hand or viewport changes. Multiplayer round flow now shows the deciding round's solution screen before the series screen, and Play Again (host only) returns the whole room to its lobby so the rules can be changed before the next match. Numbers are evaluated by a 50-digit Decimal engine: the interface exposes up to 32 decimal places, defaults to five, and a DECIMALS slider in the gameplay sidebar reveals more live on the target, board headers, equation ribbon and results. The forty catalogued constants carry full-precision decimal strings, typed exact targets keep every digit (including over the multiplayer wire), and puzzle generation probes candidates with fast doubles before rebuilding the chosen reference board exactly. The blind card auto-shrinks long targets so a high-precision target such as π fits. When approximations are enabled, the lobby's scoring mode (cost-first, balanced, accuracy-first) adds a weighted accuracy penalty to the solution score; the HUD's breakdown itemises it and the displayed total includes it. New multiplayer players get a randomized playful handle (two word banks, over a thousand combinations) instead of the generic "Player". Winning submissions now carry a sanitized board snapshot, and the round-end screen replays that board in card form (grouped cards and operator headers) beneath the equation. The workspace origin is the centre of the felt, and both dealt and tidied grids are centred by their visible card boxes, so Center View (pan 0,0) frames a tidy board correctly. Board pieces stack by recency: selecting a card or picking it up lifts it above its neighbours, it keeps that layer when dropped, and merged/split groups inherit the layer of the piece just handled. Ungrouping fans the two halves to a randomly chosen side (stepping around neighbours in that same direction), so repeated splits no longer walk the board and camera rightward. The score widget now bills the board as it is built: operator and forbidden-move costs are summed across every group, while accuracy still waits for a single finished group. The target setting also has a famous-constants mode: forty catalogued constants (π, e, Euler's γ, φ, and more) can be pinned in the lobby or dealt at random each round, the lobby shows the chosen constant's name and meaning, the in-game blind card names and explains it, and choosing the mode fills in a 2% error band so irrational targets stay playable. Every round carries its `constantId`, so multiplayer clients show the same constant the server dealt. Exact targets are no longer typed in the lobby: the host (or solo player) gets a pre-round chooser before the opening deal and every next round, the chosen number rides on `start-match`/`next-round`, and the server rejects a manual deal with `target-required` when the target is missing or invalid. The dialog remembers the last number as its starting value, validates the range, and closes without dealing on cancel or Esc. Two more operator groups are in: analysis (exp, ln, binary log base a) and combinatorics (COMB, PERM, STR2, double factorial, subfactorial), with exact integer checks and clear domain/overflow errors. Operator settings now keep a master switch per group plus per-operator overrides, so the lobby can turn a whole group on at once or leave just one operator out; the effective set drives the rails and hotkeys, and an all-off table auto-enables Add when a match starts. The lobby's operator area shows a group header with an n/total count and one chip per operator. Daily and weekly puzzles now live on the main menu: each UTC day/ISO week deterministically generates a named hand, target and operator recipe (medium four-to-five-card daily, extreme six-to-eight-card weekly), the target is derived from a valid all-cards reference expression, and players submit only boards that use every dealt card. Boards are ranked low-to-high, the top three show in the hub and above the felt, and the table server exposes `/puzzles/:kind/:key/leaderboard` with a persistent JSON store under `data/puzzle-leaderboards.json`; when that HTTP host is unavailable the scores fall back to localStorage. The Caddy config now routes `/puzzles/*` with `/ws` and `/health`. Optional opening binds are in: Dragon runs and Rook rank stacks fuse deterministically at the deal, the lobby can toggle each kind, set requirements (Dragon 2–6, Rook 2–5) and cap total binds, and bound groups are free, locked products that cannot be ungrouped; every workspace, reset, multiplayer round and puzzle uses the same deal, bind-themed daily/weekly recipes build their target from the locked starting groups, and submissions are validated against the deterministic bind formations. The gameplay HUD now fits any window height: the score rail (blind card, decimals, cost) scrolls inside its own column while the workspace tabs and round controls stay pinned, and its blocks keep their natural height instead of being squashed, so a famous-constant card or a 32-digit target can no longer clip the HUD or push the buttons off-screen. Table Setup is viewport-locked and its settings form is split into five dashed sections (Deal & match, Target, Opening binds, Operators, House rules) that scroll in their own panel, keeping the deal button on screen; below 900px the lobby falls back to page scrolling so each panel keeps a full scroll area.
